# Система записи пациентов к стоматологу (MVP)

Обзорный документ о реализованном MVP: цель, границы, принятые решения, история выполнения задач, запуск тестов и известные ограничения. Подробности по фичам — в отдельных документах (список ниже). Исходный план лежал в `docs/plans/clinic-mvp.md`; после реализации он удалён, его содержание перенесено сюда.

Статус: реализовано и принято, 2026-11-26. Результаты на момент приёмки: API-тесты 241, unit-тесты frontend 244, e2e 50 — все зелёные; `npm run lint` и `npm run build` без ошибок; `build/smoke.sh` пройден.

## Цель

SPA для записи пациентов на приём к врачу в небольшой клинике. Внутренняя система без доступа в интернет: пациенты в ней не работают, записывают их врачи и администраторы. Стек: React 19 + Vite (только CSR), NestJS, SQLite из `node:sqlite` (Node 24), Jest, Playwright, Docker. Монорепо на npm workspaces (`backend`, `frontend`, `tests`).

## Границы

Входит:
- вход по magic link и по логину и паролю, сессии на 30 дней, rate limit входа;
- роли root, администратор, врач; карточки врачей, добавление и редактирование врачей и администраторов, деактивация;
- свободные окна врача, запись пациента (от 1 часа, шаг 30 минут), отмена будущих записей, письмо врачу о новой записи;
- интерфейс на RU, EN, GR; письма на языке интерфейса того, кто выполнил действие;
- развёртывание в Docker с БД во внешнем volume.

Сознательно не входит в MVP: регистрация пациентов, отчёты, напоминания пациентам, редактирование уже созданной записи, перенос записи, HTTPS и прод-харднинг.

## Принятые уточнения (по ответам пользователя)

| Вопрос | Решение |
|---|---|
| Как добавить администратора | В форме «Добавить врача» root видит выбор роли «Врач / Администратор». Для администратора скрыты специализация, кабинет, дни и время. Администраторы показываются в «Карточках врачей» только root и помечены ролью |
| Логин и пароль | В форме добавления и редактирования есть необязательные поля «Логин» и «Пароль». Без них пользователь входит только по magic link. Пароль хранится в виде хеша (scrypt) |
| Длина записи | От 1 часа, шаг 30 минут, запись занимает несколько смежных слотов. В `Appointments` добавляется `endDate` |
| Шаг времени | 30 минут: 00:00, 00:30 … 24:00. Время окончания должно быть больше времени начала (в описании условие записано наоборот, это опечатка) |
| Отмена записи | Кнопка «Отменить» в таблице на странице «Записи» у будущих активных записей, с попапом подтверждения. Запись не удаляется, а получает статус `cancelled`, и её слот снова свободен |
| Что видит врач | На странице «Записи» — только свои записи. Отменяет только свои будущие. Записывает пациентов только к себе |
| Кабинет и пациент | В форму врача добавляется поле «Кабинет». В таблице «Записи» дополнительно показываются имя и телефон пациента |
| «Форма записи» | Пункта меню нет: форма открывается только из «Запись на приём» с выбранным слотом. Без слота (прямой URL, перезагрузка) — редирект на «Запись на приём» |
| Гость | Без входа доступны «Карточки врачей» (только просмотр) и страница входа. Остальные страницы ведут на `/login` |
| Rate limit | На оба маршрута входа: 5 запросов за 15 минут на один email или логин и 20 за 15 минут на один IP. Иначе ответ 429. Абзац про Tailscale в `email.md` к проекту не относится |
| Root | Логин `root`, пароль `root1234` («roor» в описании — опечатка), email `root@clinic.local` |
| Язык | По умолчанию RU, выбор языка хранится в localStorage. Коды языков: `ru`, `en`, `el` (в интерфейсе подпись «GR»). Письма уходят на языке интерфейса того, кто выполнил действие. Переводы лежат в json на фронте и на бэке |
| Почта | В dev и e2e используется Mailpit в docker-compose. В API-тестах — транспорт `memory` с перехватом писем. В рабочей среде SMTP настраивается через env |
| Часовой пояс | `CLINIC_TZ`, по умолчанию `Europe/Athens`. В БД время хранится в Unix seconds. API принимает и отдаёт дату и время в часовом поясе клиники строками `YYYY-MM-DD` и `HH:mm` |

Решения, которые принял исполнитель там, где описание проекта молчит:
- Окна для записи показываются в правом столбце, потому что левый занят списком и календарём.
- Деактивированный пользователь не может войти, его сессии удаляются.
- Admin и root видят в карточках деактивированных врачей с пометкой, иначе их нельзя было бы снова активировать. Гость и врач видят только активных.
- Admin управляет только врачами. Root управляет врачами и админами. Самого root через API изменить нельзя.
- Второй кнопкой в режиме входа по логину и паролю будет «Войти по email» — она возвращает к форме с email.

## Архитектура кратко

- **Backend** (`backend/src`): модули `db` (миграции, сиды), `clock` (подменяемое время), `auth`, `users`, `appointments`, `mail`, `common`, `i18n`. `createApp(options)` в `app.factory.ts` — единая точка сборки приложения для `main.ts` и API-тестов (опции: `dbPath`, `now`, `mail: 'smtp' | 'memory' | 'failing'`, `seedDev`, `appUrl`, `timezone`, `staticDir`). Все пути API начинаются с `/api`, ошибки приходят как `{ code, fields? }`. Время в часовом поясе считается через `luxon`. В Docker backend раздаёт и статику frontend.
- **Frontend** (`frontend/src`): React Router, `AuthContext`, `api/client.ts`, i18n на `react-i18next`, компоненты `Header`, `LanguageSelect`, `ConfirmDialog`, `DatePicker`, страницы `RecordsPage`, `BookingPage`, `BookingFormPage`, `DoctorsPage`, `DoctorFormPage`, `LoginPage`, `MagicLinkPage`. Стили — обычный CSS по БЭМ.
- **БД**: таблицы `Users`, `Appointments`, `MagicLinks`, `Sessions`, `schema_migrations`; одна миграция `1 initial` (см. [users.md](users.md) и [data-model.md](../specs/design/data-model.md)).
- **Развёртывание**: один образ, `docker-compose` с `app` и `mailpit`, БД в volume (см. [deploy.md](deploy.md)).

## Как запускать проверки

Команды выполняются из корня репозитория, нужен Node.js 24 (`.nvmrc`); подробности — [docs/guide/dev-setup.md](../guide/dev-setup.md).

| Что | Команда | Примечание |
|-----|---------|------------|
| API-тесты (Jest + supertest) | `npm run test:api` | `tests/api/*.spec.ts`; каждый файл поднимает `createApp` с временной БД, `mail: 'memory'` и управляемыми часами |
| Unit-тесты frontend (Jest + jsdom + RTL) | `npm run test:frontend` | `tests/frontend/*.spec.tsx`; запросы к API мокаются |
| E2E (Playwright) | `docker compose -f build/docker-compose.yml up -d mailpit`, затем `npm run test:e2e` | нужен запущенный Mailpit (SMTP `:1025`, API `:8025`); Playwright сам собирает и поднимает backend на `:3100` (временная БД, `SEED_DEV=true`) и frontend на `:4173` |
| Линтер | `npm run lint` | ESLint + TypeScript для всех workspaces |
| Сборка | `npm run build` | backend и frontend |
| Smoke развёртывания | `bash build/smoke.sh` | нужен Docker; собирает образ, создаёт врача, пересоздаёт контейнер, проверяет данные и раздачу frontend |

Ручная проверка в браузере (dev-режим по `dev-setup.md`): войти как `root` / `root1234`; добавить врача; записать пациента и проверить письмо в Mailpit (http://localhost:8025); отменить запись; переключить языки.

Имя каждого теста начинается с AC-ID (например, `AC-AUTH-04: …`). Сопоставление AC-ID и тестов — в таблицах документов по фичам и в [README.md](README.md).

## Известные ограничения и заметки

- **Root через API не меняется.** Пароль root меняется заменой хеша в поле `pass` строки root в БД (или доработкой смены пароля).
- **Окна считаются по минутам суток** и не учитывают переход на летнее время.
- **Просроченный magic link в e2e не проверяется**: истечение 30 минут в e2e не воспроизвести; сценарий покрыт API-тестом AC-AUTH-04 и unit-тестами frontend (AC-UI-LOGIN-05).
- **Контейнер работает под uid 1000** (пользователь `node`): папка с БД на хосте должна быть доступна ему на запись.
- Rate limit входа хранится в памяти процесса (при перезапуске сбрасывается) и считает по `req.ip` без `trust proxy`.
- Календарь «Записи на приём» определяет «сегодня» и день недели по часам браузера, а не по `CLINIC_TZ`; сервер проверяет слот в поясе клиники.
- Миграция одна (`1 initial`); любые изменения схемы — только новыми миграциями.
- Dev-пользователи (`SEED_DEV=true`) и стандартный root — учебные данные, в рабочей среде их не использовать.
