# Запись на приём: свободные окна, записи, отмена, письма

Расчёт свободных окон врача, создание и отмена записей, письмо врачу о новой записи, страницы «Записи», «Запись на приём» и «Форма записи».

Статус: реализовано, 2026-11-26. Обзор MVP — [clinic-mvp.md](clinic-mvp.md).

## Что реализовано

- **API**: `GET /api/doctors/:id/free-windows?date=YYYY-MM-DD`, `GET /api/appointments?date=&doctorId=`, `POST /api/appointments`, `POST /api/appointments/:id/cancel`. Все маршруты требуют входа (гость получает 401).
- **Письмо врачу** о новой записи на языке интерфейса того, кто создал запись (`lang` в теле запроса): «На приём записан {пациент}, {дд.мм.гггг} {начало}–{конец}. Контактный телефон: {телефон}». Шаблоны — `mail.appointment.*` в `backend/src/i18n/{ru,en,el}.json`, транспорт — nodemailer по env `SMTP_*`.
- **Frontend**: `RecordsPage` (`/records`), `BookingPage` (`/booking`), `BookingFormPage` (`/booking/form`). Все три доступны врачу, admin и root.

## Поведение и решения сверх описания

### Окна и время

- В БД время хранится в Unix seconds (`appointmentDate`, `endDate`). API принимает и отдаёт дату `YYYY-MM-DD` и время `HH:mm` в часовом поясе клиники (`CLINIC_TZ`, по умолчанию `Europe/Athens`).
- Запись длится от 1 часа, шаг 30 минут, занимает несколько смежных слотов; конец записи может быть `24:00`.
- **Свободное окно** — промежуток рабочего времени врача между активными записями длиной от 60 минут. Отменённые записи окно не занимают. В нерабочий день и для прошедших дат ответ `[]`. Для сегодняшней даты окна начинаются не раньше ближайшей отметки, кратной 30 минутам, строго после текущего момента.
- `free-windows` для деактивированного врача, не-врача или неизвестного id даёт 404.

### Создание записи

- Порядок проверок: валидация тела (400 `VALIDATION_ERROR` со списком полей), права (врач записывает только к себе, иначе 403), существование врача (404), доступность слота (400 `SLOT_UNAVAILABLE`: нерабочий день, вне рабочих часов, прошлое, деактивированный врач), занятость (409 `SLOT_TAKEN`).
- Проверка пересечения и вставка выполняются в одной транзакции `BEGIN IMMEDIATE`, поэтому одновременные запросы не создают двойную запись.
- Имя пациента (до 200 символов) и телефон (до 32) обязательны, комментарий (до 1000) нет. Заполняются `createDate` и `creatorId`.
- Если письмо не ушло (SMTP недоступен), запись сохраняется, в ответе `mailSent: false`. Frontend показывает отдельное сообщение о неотправленном уведомлении.

### Список и отмена

- `GET /api/appointments?date=` возвращает записи за день, отсортированные по началу. Admin и root видят всех врачей или одного (`doctorId`), врач всегда только свои (`doctorId` в запросе игнорируется). В объекте есть `canCancel`: запись активна, начало в будущем, а для врача она ещё и своя.
- Отмена не удаляет запись: статус `cancelled`, `cancelDate`, `cancelerId`; слот снова свободен. Отмена прошедшей, текущей или уже отменённой записи — 400 `NOT_CANCELLABLE`; врач отменяет только свои (чужая — 403).

### Frontend

- **Записи.** Слева выпадающий список врачей («Все» по умолчанию; у врача только он сам, список заблокирован) и календарь, справа таблица: заголовок — выбранная дата, колонки время, врач, кабинет, пациент, телефон, действия. Отменённые записи помечены. Кнопка «Отменить» есть только при `canCancel`, открывает попап подтверждения; после «Да» строка обновляется из ответа API. При отсутствии записей — «Записей нет».
- **Запись на приём.** Подсказка «Выберите врача и дату» стоит под заголовком страницы, пока врач или дата не выбраны. Слева список активных врачей (врачу его самого, список заблокирован) и календарь, в котором недоступны прошлые дни и нерабочие дни врача. Справа список свободных окон, выбор времени начала (шаг 30 минут, окно должно вмещать минимум час), длительность (от 1:00 с шагом 30 минут до конца окна, по умолчанию 1:00) и кнопка «Записать», неактивная, пока время не выбрано. Если окон нет — «Нет свободного времени». Смена врача или даты сбрасывает время и длительность. Окна читаются заново при каждом выборе врача и даты.
- **Форма записи.** Выбранный слот передаётся через `state` роутера (при перезагрузке страницы теряется). Врач, дата и время только для чтения. Имя и телефон обязательны (пустые поля дают ошибки и попап не открывается). «Записать» открывает попап «Подтвердить запись»; «Да» создаёт запись и переводит на «Запись на приём» с сообщением об успехе; «Нет» закрывает попап. `SLOT_TAKEN` и `SLOT_UNAVAILABLE` показываются текстом ошибки, пользователь остаётся на форме. «Назад» возвращает на «Запись на приём». В меню формы нет; открытая без слота (прямой URL, перезагрузка) она перенаправляет на «Запись на приём» (`replace`).

## Ограничения

- Окна рассчитываются по минутам суток и не учитывают переход на летнее время: в день перевода часов окна и записи вокруг «лишнего» или «пропавшего» часа могут считаться неверно.
- Редактирования и переноса записи нет, только отмена. Пациенты не регистрируются, напоминания пациентам не отправляются; письмо уходит только врачу.
- Деактивированный врач сохраняет свои будущие записи (они не отменяются автоматически).
