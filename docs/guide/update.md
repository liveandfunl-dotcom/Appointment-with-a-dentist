# Обновление

БД лежит во внешней папке (`build/data/`) и при обновлении сохраняется. Миграции применяются автоматически при старте контейнера.

1. Сделайте бэкап БД (см. [backup.md](backup.md)).
2. Получите новую версию кода (`git pull` или новая копия репозитория).
3. Пересоберите образ и пересоздайте контейнеры из корня репозитория:

   ```bash
   docker compose -f build/docker-compose.yml up -d --build
   ```

   Контейнер `app` будет заменён новым, папка `build/data/` не затрагивается. Mailpit перезапускается только при изменении его настроек.
4. Проверьте `http://<сервер>:3000/api/health` — ответ `{"status":"ok"}`.

Если интернета на сервере нет, соберите образ на другой машине и перенесите его: `docker save`, затем `docker load` на сервере (в `docker-compose.yml` для этого понадобится заменить `build:` на `image:`).

## Откат

Верните прежнюю версию кода, выполните ту же команду `up -d --build`. Если новая версия успела применить миграции БД, восстановите БД из бэкапа (см. [backup.md](backup.md)).
