# Развёртывание

Приложение — один Docker-образ (backend NestJS + собранный frontend) и вспомогательный Mailpit. Доступ в интернет во время работы не нужен; образы собираются заранее на машине с доступом к реестру.

## Первый запуск

Команды выполняются из корня репозитория.

```bash
cp build/.env.example build/.env      # поправьте значения (таблица ниже)
mkdir -p build/data
docker compose -f build/docker-compose.yml up -d --build
```

Приложение: http://localhost:3000 (порт задаёт `APP_PORT`). Mailpit: http://localhost:8025.

- **Права на папку данных.** Приложение внутри контейнера работает под пользователем `node` (uid 1000). На Linux папка `build/data` должна быть доступна ему на запись: `sudo chown 1000:1000 build/data`. Иначе приложение не стартует (ошибка открытия БД).
- **БД** лежит в `build/data/clinic.db` (volume `./data:/data` относительно `build/`). При первом старте создаются схема и пользователь root.
- **Почта.** По умолчанию письма уходят в Mailpit (они только копятся там и пациентам не доставляются). Для реальной отправки задайте в `build/.env` `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` вашего SMTP-сервера.
- **`APP_URL`** должен быть адресом, по которому пользователи открывают систему: он попадает в ссылки magic link.
- **Для рабочей среды** уберите `SEED_DEV=true` (иначе создаются тестовые врачи с известными паролями).

## Учётная запись root

Логин `root`, пароль `root1234`, email `root@clinic.local`. Проект учебный, это не рабочая конфигурация: не оставляйте эти данные на доступном из сети сервере. Сменить пароль root через API или интерфейс в MVP нельзя (root через API не изменяется); при необходимости замените хеш в поле `pass` строки root в `clinic.db` или доработайте смену пароля. Тестовых пользователей (`SEED_DEV`) в рабочей среде не создавайте.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|------------|--------------|------------|
| `PORT` | `3000` | порт HTTP внутри контейнера |
| `DB_PATH` | `/data/clinic.db` в образе (`./data/clinic.db` без Docker) | файл SQLite |
| `STATIC_DIR` | `/app/frontend-dist` в образе, не задан в dev | каталог собранного frontend; если задан, backend раздаёт его и отдаёт `index.html` для любого GET вне `/api` |
| `APP_URL` | `http://localhost:3000` | база ссылки magic link в письмах |
| `CLINIC_TZ` | `Europe/Athens` | часовой пояс клиники |
| `SEED_DEV` | не задан | `true` — создать тестового администратора и 5 врачей |
| `SMTP_HOST` | `localhost` (в compose `mailpit`) | SMTP-сервер |
| `SMTP_PORT` | `1025` | порт SMTP |
| `SMTP_SECURE` | `false` | `true` — TLS с первого байта (порт 465); для 587/STARTTLS не задавайте |
| `SMTP_USER` / `SMTP_PASS` | пусто | авторизация SMTP; пусто — без неё |
| `SMTP_FROM` | `Clinic <noreply@clinic.local>` | адрес отправителя |
| `APP_PORT` | `3000` | только compose: порт приложения на хосте |
| `MAILPIT_SMTP_PORT` / `MAILPIT_UI_PORT` | `1025` / `8025` | только compose: порты Mailpit на хосте |
| `DATA_DIR` | `./data` (относительно `build/`) | только compose: папка с БД на хосте |

## Проверка развёртывания

`bash build/smoke.sh` собирает образ, поднимает стек во временной папке, создаёт врача, пересоздаёт контейнер и проверяет, что данные сохранились (AC-DEPLOY-01). Если стандартные порты заняты:

```bash
APP_PORT=3100 MAILPIT_SMTP_PORT=1125 MAILPIT_UI_PORT=8125 bash build/smoke.sh
```
