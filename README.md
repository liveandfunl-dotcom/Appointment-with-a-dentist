# Appointment-with-a-dentist

Система записи пациентов на приём к стоматологу — внутреннее веб-приложение клиники. Врачи и администраторы ведут расписание и записывают пациентов, гости видят карточки врачей.

**Стек:** React 19 + Vite (frontend), NestJS (backend), SQLite (встроенный в Node.js), Docker. Тесты — Jest и Playwright.

## Веб-ссылка

Развёрнутый экземпляр: **http://94.156.35.108:8081**

Проверка работоспособности: http://94.156.35.108:8081/api/health → `{"status":"ok"}`.

## Как пользоваться

Интерфейс доступен на русском, английском и греческом — язык переключается в шапке (RU / EN / GR) и запоминается в браузере.

### Роли

| Роль | Что доступно |
|------|--------------|
| гость | просмотр карточек врачей и поиск по ним |
| врач | свои записи, запись пациентов к себе |
| администратор | записи всех врачей, запись к любому врачу, добавление и редактирование врачей |
| root | всё, что администратор, плюс создание администраторов |

### Вход

Нажмите **«Войти»** в шапке. Два способа:

- **По email** — введите почту, нажмите «Авторизоваться» и откройте ссылку из письма (magic link). Ссылка одноразовая и действует ограниченное время.
- **По логину и паролю** — кнопка «Войти по логину и паролю».

Выход — кнопка **«Выйти»** в шапке с подтверждением.

### Тестовая учётная запись root

Root создаётся автоматически при первом старте, в том числе в Docker:

| Логин | Пароль | Email |
|-------|--------|-------|
| `root` | `root1234` | `root@clinic.local` |

Войдите под root по логину и паролю, затем через «Добавить врача» создайте врачей и администраторов.

Это учебная конфигурация. На сервере, доступном из сети, известный пароль root опасен. В MVP сменить его через интерфейс или API нельзя: замените хеш в поле `pass` строки root в `clinic.db` (см. [deploy.md](docs/guide/deploy.md#учётная-запись-root)). Когда письма идут через настоящий SMTP, root входит только по логину и паролю. Ссылка для входа уходит на `root@clinic.local`, а этот адрес не существует. Локально такое письмо видно в Mailpit.

### Основные сценарии

1. **Записать пациента** — «Запись на приём»: выберите врача и дату (доступны только приёмные дни врача, не раньше сегодняшнего), затем время начала и длительность в свободном окне, нажмите «Записать». На следующем шаге введите ФИО и телефон пациента, при необходимости комментарий, и подтвердите. Врачу уходит письмо о новой записи.
2. **Посмотреть записи** — «Записи»: выберите врача (администратор может выбрать «Все») и дату в календаре. В таблице — время, врач, кабинет, пациент и телефон.
3. **Отменить запись** — в таблице записей кнопка «Отменить» с подтверждением. Отменённая запись остаётся в таблице с отметкой.
4. **Карточки врачей** — список с поиском по фамилии, имени и специализации. Администратор редактирует карточку иконкой ✎ и добавляет врача через «Добавить врача» (ФИО, специализация, контакты, кабинет, приёмные дни и часы, логин и пароль). Врача можно деактивировать — к нему больше нельзя записать.

Подробно экраны и тексты описаны в [docs/specs/ui/screens.md](docs/specs/ui/screens.md).

## Сборка

Нужны **Node.js 24** (см. `.nvmrc`) и **Docker** (для Mailpit и e2e-тестов). Команды выполняются из корня репозитория (npm workspaces).

```bash
npm install          # зависимости всех пакетов
npm run lint         # ESLint + TypeScript
npm run build        # сборка backend и frontend
```

### Локальный запуск для разработки

```bash
docker compose -f build/docker-compose.yml up -d mailpit       # почтовая ловушка, UI: http://localhost:8025
SEED_DEV=true SMTP_HOST=localhost npm run dev:backend          # backend: http://localhost:3000
npm run dev:frontend                                           # frontend: http://localhost:5173
```

`SEED_DEV=true` создаёт тестового администратора и пять врачей; учётные записи перечислены в [docs/guide/dev-setup.md](docs/guide/dev-setup.md). Письма со ссылками для входа смотрите в Mailpit.

### Тесты

```bash
npm run test:api        # API (Jest)
npm run test:frontend   # компоненты frontend (Jest + RTL)
npm run test:e2e        # сквозные сценарии (Playwright), нужен запущенный Mailpit
```

## Развёртывание

Приложение — один Docker-образ (backend + собранный frontend). Файл БД хранится во внешней папке (volume) и переживает пересоздание контейнера.

```bash
cp build/.env.example build/.env      # заполните переменные (см. ниже)
mkdir -p build/data
sudo chown 1000:1000 build/data       # Linux: контейнер работает под uid 1000
docker compose -f build/docker-compose.yml up -d --build
```

Основные переменные в `build/.env`:

| Переменная | Назначение |
|------------|------------|
| `APP_PORT` | порт приложения на хосте (по умолчанию `3000`) |
| `APP_URL` | адрес, по которому пользователи открывают систему, — попадает в ссылки для входа из писем (например, `http://94.156.35.108:8081`) |
| `CLINIC_TZ` | часовой пояс клиники (по умолчанию `Europe/Athens`) |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` | SMTP-сервер для писем; по умолчанию письма уходят в Mailpit и пациентам не доставляются. `SMTP_SECURE=true` — для порта 465 |
| `SEED_DEV` | `true` — тестовые пользователи; **в рабочей среде не задавайте** |

Файл `build/.env` содержит пароли — не добавляйте его в git.

После запуска проверьте `http://<сервер>:<APP_PORT>/api/health`.

### Обновление и бэкап

- **Обновление:** сделайте бэкап, получите новый код (`git pull`) и повторите `docker compose -f build/docker-compose.yml up -d --build`. Миграции БД применяются автоматически при старте.
- **Бэкап:** вся база — файл `build/data/clinic.db`; без остановки приложения: `sqlite3 build/data/clinic.db ".backup 'backup/clinic-$(date +%F).db'"`.
- **Проверка развёртывания:** `bash build/smoke.sh` поднимает стек во временной папке и проверяет, что данные сохраняются при пересоздании контейнера.

Подробнее: [deploy.md](docs/guide/deploy.md), [update.md](docs/guide/update.md), [backup.md](docs/guide/backup.md).
